## 작업 요약 (3줄)

1. **§A 근본 원인은 이벤트 배선 누락이었다.** 활동에서 마감 알림을 누르면 `openPanel("task")`가 `SIDE_PANEL_EVENT`만 쏘는데, 업무를 그리는 `TaskDetailPanel`은 `TASK_PANEL_EVENT`만 듣는다. 아무도 그리지 않는 사이 `SidePanel`이 레이아웃만 420px 줄여 **"간격만 좁아지고 내용이 안 보이는"** 정확한 증상이 났다.
2. **§B 표시·카운트·토스트는 이미 동작하고 있었고, 진짜 결함은 필터 레일이었다** — 사람 탭에 `마감 9`, 시스템 탭에 `멘션 1·승인 3` 처럼 **그 탭에 있을 수 없는 숫자**가 떠서 아무리 처리해도 안 줄어드는 것처럼 보였다. 레일을 채널별로 갈랐다.
3. §C 시스템 알림 액션바에서 리액션·답글을 뺐고, §D 내 업무 기본 정렬·완료 필터·URL 반영, §E 완료 업무 D+ 표기를 완료일로 바꿨다. **§F는 데이터 미입력이 주원인이고, 곁가지 코드 결함 1건을 함께 고쳤다.**

## §A 재현 결과와 근본 원인

### 재현

`/activity` → **시스템** 탭 → 마감 알림 클릭. (기본 탭이 **사람**이라 마감 알림은 시스템 탭에 있다.)

수정 전 관측값:

```
url          ?panel=task:72
gpanelOpen   true          ← body 에 gpanel-open 이 붙어 .main 이 420px 줄어든다
gpanelCount  0             ← 그런데 패널 내용은 0개
tdpCount     0             ← 업무 패널도 안 떴다
```

→ 화면에는 **420px 짜리 빈 여백만** 생긴다. 팀원이 말한 "간격만 좁아지고 내용이 보이지 않음"과 일치한다.

### 근본 원인

업무 패널만 **다른 이벤트 채널**을 쓰는데, 활동에서 여는 경로가 그 채널로 통지하지 않았다.

| 컴포넌트 | 듣는 이벤트 | 그리는 것 |
|---|---|---|
| `SidePanel` | `SIDE_PANEL_EVENT` | signal · member · decision (**task 제외**) |
| `TaskDetailPanel` | `TASK_PANEL_EVENT` | task |

`lib/side-panel.ts`의 `openPanel(kind, id)`는 **`SIDE_PANEL_EVENT`만** 발행한다.
따라서 `openPanel("task", 72)`은
- `SidePanel` → 이벤트를 받아 `ref`를 세팅 → `document.body.classList.add("gpanel-open")` (**여백 생성**)
- 그러나 렌더는 `ref.kind !== "task"` 조건에서 걸러져 **아무것도 안 그림**
- `TaskDetailPanel` → **이벤트를 못 들음** → 안 뜸

`/tasks` 목록에서 행을 클릭할 때는 `openTaskPanel()`(= `TASK_PANEL_EVENT`)을 쓰기 때문에 정상이었다.
**활동에서 여는 경로에서만** 재현되는 이유가 이것이다.

### 수정

| 파일 | 내용 |
|---|---|
| `lib/side-panel.ts` | `openPanel()`에서 `kind === "task"`면 `TASK_PANEL_EVENT`도 함께 발행 |
| `components/SidePanel.tsx` | `gpanel-open` 토글 기준을 `ref` → `active`로. 업무는 여기서 안 그리므로 폭도 줄이지 않는다 |

기존 컴포넌트를 그대로 재사용했다. 업무 패널을 새로 구현하지 않았다.

### 수정 후 실측

```
url          ?panel=task:72
gpanelOpen   false     ← 빈 여백 없음
tdpCount     1         ← 원본 업무가 열림
dateInputs   2         ← 시작일·기한 편집 가능
```

기한을 실제로 바꿔 저장까지 확인: `2026-08-04 → 2026-09-15` 저장 → 새로고침 후에도 유지. **검증 뒤 원래 값으로 되돌렸다**(2026-09-15 로 남은 업무 0건 확인).

**회귀 확인** — 논의 패널은 여전히 `.gpanel` 420px 로 정상, 업무 목록에서 행 클릭 시 `.tdp` 1개 · `.gpanel` 0개(중복 오픈 없음).

## §B 읽음 처리가 "안 변하는" 것처럼 보인 이유

먼저 지시서가 요구한 4가지를 계측했다. **3가지는 이미 동작하고 있었다.**

| 요구 | 계측 결과 |
|---|---|
| 1. 안읽음 = 제목 굵게 + 좌측 코랄 점 | **이미 적용됨** — 안읽음 `font-weight 700` + `::before` 코랄 점 6px / 읽음 `400` + 점 없음 |
| 2. 읽음 후 필터 레일 카운트 즉시 감소 | 동작하나 **레일 자체가 잘못돼 있었음** ↓ |
| 3. 토스트 + 실행취소 | **이미 적용됨** — `"1건 읽음 처리했어요" [실행취소]` |
| 4. "여기까지 읽음" 구분선 | **이미 적용됨** — 1개 렌더 확인 |

### 진짜 결함 — 필터 레일이 채널을 무시했다

`RAIL_KINDS` 6종을 **채널과 무관하게** 항상 렌더하고 있었다. `counts.byKind` 역시 채널 구분이 없다.

수정 전:

| 탭 | 레일 |
|---|---|
| 사람 | 전체 5 · 멘션 1 · 배정 1 · 답글 · 승인 3 · **마감 9** · 결정 |
| 시스템 | 전체 9 · **멘션 1 · 배정 1 · 답글 · 승인 3** · 마감 9 · 결정 |

시스템 탭에서 마감 알림을 아무리 읽어도 눈에 띄는 `멘션 1`·`승인 3`은 그대로다.
게다가 시스템 탭은 숫자 대신 **점**만 표시하는 규격이라(MD-P-007 §B) 탭에서도 변화가 안 보인다.
**"처리해도 화면이 안 달라진다"는 체감이 여기서 나온다.**

### 수정

`lib/activity-kinds.ts`에 `KIND_CHANNEL` 상수를 두고(`classify()`와 같은 규칙), 레일을 현재 채널의 종류만 그리도록 했다. 채널을 바꿀 때 그 채널에 없는 종류 필터가 걸려 있으면 `전체`로 되돌린다 — 안 그러면 빈 목록만 남고 이유가 안 보인다.

수정 후 실측:

| 탭 | 레일 |
|---|---|
| 사람 | 전체 5 · @멘션 1 · ◱배정 1 · ↩답글 |
| 시스템 | 전체 9 · ⏱마감 9 |

읽음 처리 전후 실측: 안읽음 **6 → 5**, 레일 전체 **6 → 5**, 탭 배지 **6 → 5**, 토스트 `1건 읽음 처리했어요 [실행취소]`.

- 완료 → `완료 2026-07-03`
- 중단 → `중단 YYYY-MM-DD`
- 완료일이 없으면 `완료`만. **날짜를 추정하지 않는다.**
- 미완료 → 기존 `D+n · D-DAY · D-n` 유지
