## §C 권한 전수 점검 — **우회 1건 발견·수정**

member 세션과 lead 세션으로 같은 URL을 때려 비교했다. **26건 검사.**
검사용 임시 member 계정은 만들었다가 검증 후 삭제했다(actor·account·activity_log 잔여 0건).

### 발견한 구멍 — `/api/goals/[id]/projects`

`/api/goals/[id]` 는 개인 목표 접근을 403으로 막는데, **하위 라우트 `/projects` 는 `requireSession()` 만 걸려 있었다.**
그래서 member 가 남의 개인 목표에 대해

- **GET** — 연결된 프로젝트 목록 + 전체 후보 목록을 읽을 수 있었고
- **POST / DELETE** — 프로젝트를 **연결·해제까지** 할 수 있었다

지시서가 말한 "클라이언트 숨김만으로 처리된 곳"에 정확히 해당한다. 화면에서 안 보일 뿐 API 는 열려 있었다.

**수정** — `/api/goals/[id]` 와 같은 규칙의 `guardGoal()` 을 GET·POST·DELETE 세 곳에 적용:

| 목표 종류 | 읽기 | 쓰기 |
|---|---|---|
| 개인 | 본인 · 팀장 | 본인만 |
| 팀 | 전원 | 팀장만 |

수정 후 실측: 타인 개인 목표 #10 에 대해 member **403** / lead **200**.

### D-3. N+1 — **홈 요약에서 발견**

Postgres 문장 로그로 요청 1건당 실제 SQL 실행 수를 셌다.

| 화면 | SQL | 판정 |
|------|---:|---|
| **홈 요약** `/api/home/summary` | **167** | ⚠ **N+1** |
| 프로젝트 워크스페이스 | 18 | · 확인 권장 |
| 월간 리포트 | 16 | · 확인 권장 |
| 목표-프로젝트 연결 | 13 | · 확인 권장 |
| 활동 인박스 | 6 | 정상 |
| 목표 목록 | 4 | 정상 |
| 내 업무 | 2 | 정상 |
| 프로젝트 목록 | 1 | 정상 |

**원인 특정** — `lib/home.ts:206` `sparkSeries()` 가 **하루에 한 번씩 7일치를 순차 조회**하고,
이걸 openSpark · doneSpark · overdueSpark **3번** 호출한다. 같은 형태의
`SELECT count(*) AS n FROM task t …` 가 **66회** 반복된다.

```ts
async function sparkSeries(sqlPerDay: (day: string) => Promise<number>, today: string) {
  const out: number[] = [];
  for (let i = 6; i >= 0; i--) out.push(await sqlPerDay(addDays(today, -i)));  // ← 7회 × 3
  return out;
}
```

7일치를 `GROUP BY` 한 방으로 바꾸면 21회 → 3회가 된다.
**이번에는 고치지 않았다** — 지시서 §D 는 "점검 + 계측값 제출"이고 제약이 "새 기능 추가 금지,
안내·점검·문서화만"이라 구조 변경을 임의로 하지 않았다. **별도 지시를 주시면 처리하겠다.**
현재 응답시간(68ms)에서는 체감되지 않지만, 업무가 쌓이고 운영 왕복이 붙으면 가장 먼저 느려질 지점이다.

| 백업·복구 | "설정 상태 확인 후 보고" | **보류** | 운영 DB 콘솔 접근 수단 없음. RUNBOOK 에 확인 항목만 준비 |
| 권한 점검 | "확인" | 확인 + **1건 수정** | 실제 우회를 찾았고, 오픈 전에 열어둘 수 없는 종류라 즉시 막았다 |
