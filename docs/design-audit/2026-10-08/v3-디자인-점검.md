# 통합업무관리 v3 디자인 점검 — 보고만 (2026-10-08)

> 방법: dual-agent — A(디자인 리뷰)와 B(자동 탐지기 · 브라우저 측정 · 기술 점검)를 서로 다른 에이전트로 따로 돌린 뒤 합쳤다.
> 도구: impeccable `critique` · `audit`, ui-ux-pro-max(업무관리 SaaS 기준).
> 대상: 새 화면(v3) 아홉 + 스위치 화면. 옛 화면은 제외.
> 조건: 로컬 시드 데이터(계정 4 · 업무 38). 박정길(팀장 + 관리자)로 로그인. 로컬 DB 에서만 스위치를 켰다가 끝나고 되돌렸다.
> **코드 · 디자인 토큰은 한 줄도 바꾸지 않았다.** 프로덕션은 건드리지 않았다.
> 화면 캡처: `shots/` 폴더 — 화면마다 데스크톱 1440 · 모바일 390 각 1장, 모두 20장.

## 2. 한 줄 판정

**뼈대는 흔한 B2B 템플릿이고, 판단 규칙은 이 제품만의 것이다.**
- 템플릿 같은 부분: 파란 레일, 흰 카드에 radius 16 과 그림자, 큰 숫자 타일, 진척 링 셋.
- 이 제품만의 규칙:
  - 가오픈 D-day
  - 7일 넘게 지난 일은 회색으로 접기
  - 0건 칸은 누를 수 없게 하기
  - 저장 줄이 늘 남기
- 그런데 그 고유함이 **화면 위의 설명 문장**으로 드러나고, 시각 언어로는 드러나지 않는다.

## 3. 잘 되는 것

1. **사라지지 않는 저장 줄과, 칸 옆의 오류 사유.** 자동 저장 화면의 가장 큰 불안인 「저장됐나?」에 늘 같은 자리에서 답한다.
2. **급함 신호를 아껴 쓴다.**
   - 코랄(빨강)은 7일 이내로 지난 일에만 쓴다.
   - 카테고리 색과 상태 색이 분리돼 있다.
   - 0건 칸은 흐리게 남긴다.
3. **거르개가 정직하다.**
   - 걸린 조건이 × 칩으로 보인다.
   - 결과가 0건이면 그 조건을 다시 적어 준다.
   - 빈 목록이 고장으로 읽히지 않는다.
4. **기본기.**
   - 모든 화면 · 두 폭에서 콘솔 오류 0, 가로 넘침 0, 이름 없는 버튼 0.
   - 모션은 transform/opacity 만 쓰고, 「동작 줄이기」 설정을 존중한다.

| ⑦ 팀 | 상태를 링 색으로만 구분한다. 「5열」 · 「+1」 같은 표현. 칩·버튼 15개가 한 줄에 있다 | 색각 이상 · 첫 사용자가 읽지 못한다 | 점 + 글자로 표시한다. 「팀원 5명」 · 「+1 더보기」로 바꾼다 |
| ⑧ 구성원 | 역할 select 글자가 잘리고(「티원」) 폭이 화면 끝까지 늘어난다 | 관리 화면이 고장 나 보인다 | v3 안에서 select 기본값을 되돌린다 |
| ⑧ 구성원 | 「활성」 버튼이 상태 표시인지 동작인지 모호하다. 역할 변경이 확인 없이 즉시 저장된다 | 권한 사고 위험 | 상태 표시와 「비활성으로 바꾸기」 동작을 나눈다. 바꾼 뒤 실행 취소 토스트를 띄운다 |
| ⑧ 구성원 | 레일에서 「내 정보」도 같이 켜진다 | 위치를 잘못 알려 준다 | 경로 비교를 고친다 |
| ⑨ 내 정보 | 모바일에서 「8자 이상」이 한 글자씩 세로로 쌓이고, 라벨이 줄바꿈된다. 데스크톱에서 입력 두 칸의 시작 위치가 다르다. 비밀번호 칸에 포커스 표시가 없다 | 깨져 보인다 | 라벨을 위에 두는 세로 폼으로 바꾸고, 도움말은 입력 아래에 둔다 |
| ⑩ 스위치 | 전사에 영향을 주는 토글인데, 현재 상태 「켜짐」이 12px 회색 글씨이고 끄기 버튼이 보조 버튼 모양이다 | 위험에 비해 무게가 없다(확인 단계는 있다) | 상태를 큰 배지로 보여 주고, 확인 문구에 「모두에게 적용」을 강조한다 |
| 공통 · 레일 | 레일 묶음 제목 2.28:1, 자물쇠 항목 2.7:1. 🔒 가 이모지 · 10px 다. 4곳(캘린더 · 프로젝트 · 영역 · 설정)이 막음 화면으로 간다 | 읽기 어렵고, 누르면 막힌다 | 대비를 올린다. 자물쇠를 SVG 아이콘으로 바꾼다. 잠긴 곳은 접어 둔다 |

## 8. 사용자 유형별로 막히는 곳

- **숙련자(빠르게 처리)**
  - 업무 목록에서 ⌘K/Ctrl+K 가 안 듣는다. 대시보드에서는 광고한다.
  - 목록에서 바로 완료할 수 없다.
  - 팀 화면 5번째 열이 잘린다.
- **키보드 · 화면낭독기 사용자**
  - 본문 바로가기가 없어서, 본문까지 Tab 을 15번 눌러야 한다.
  - 레일 포커스가 파랑 위 1px 라 거의 안 보인다.
  - 새 업무 제목에 라벨 · 포커스 표시가 없다.
  - 상세 화면에 h1 이 없다.
  - 모바일 서랍에서 포커스가 새어 나간다.
- **처음 쓰는 사람**
  - 「영역」과 「카테고리」가 같은 것인지 알 수 없다.
  - 「가오픈 D-101」과 「D-25」의 차이를 알 수 없다.
  - 「◉ 내 항목」 · 「+1」 · 「5열」이 무슨 뜻인지 모른다.
  - 레일 4곳이 막음 화면이다.
  - 목표를 만드는 길이 없다.

## 9. 확인하지 못한 것

- 화면낭독기 실제 낭독, 200% 확대, 터치 제스처, 「동작 줄이기」를 브라우저로 흉내 낸 확인(코드로만 봤다).
- 저장 · 상태 변경 같은 **쓰기 동작**의 실제 피드백 — 읽기만 점검했다.
- 팀원 · 비관리자 시점의 화면 — 팀장 + 관리자 한 계정으로만 봤다.
- 실제 팀 데이터 양에서의 모습 — 로컬 시드(계정 4 · 업무 38)로만 봤다.
- 구성원 화면엔 4명만 있는데 팀 화면 · 담당자에 권정혁이 보인다. 시드 데이터 문제인지 「계정 없는 담당자」 처리인지는 확인하지 않았다.
