# 스위치를 켜기 전에 — 한 장 (MD-P-2026-073 §C)

**켜기 전에 읽는 문서다. 스위치는 아직 켜지 않았다.**
스위치 = `config` 표의 `ui_v3_enabled` 한 줄. 요청마다 읽는다(`force-dynamic`) — 캐시가 없다.
모든 사람에게 **한꺼번에** 걸린다(사람별 미리보기는 없다).

아래 숫자는 전부 **로컬에서 잰 값**이다(073 · 관리자 · 팀원 계정 둘). 프로덕션은 CC 가 못 닿아 못 쟀다.

---

## ⚠ 먼저 — 켜면 **화면으로는 못 끈다**

켜는 스위치는 옛 「설정」(`/settings`)에 있다. 그런데 켜면 `/settings` 가 **막음 화면**으로 간다
(`/settings → /v3/not-yet?k=settings`, 로컬 확인). 그래서 켠 뒤에 끄려면 화면 말고 둘 중 하나다.

| 끄는 법 | 무엇을 하나 | 로컬에서 걸린 시간 |
|---|---|---|
| ① 관리자로 로그인한 채 브라우저 콘솔에 한 줄 | 아래 명령 — 설정 API 에 `uiV3:false` | **다음 요청부터** 꺼짐 (83ms · 첫 요청에 바로) |
| ② DB 에서 줄 하나 지우기 | `DELETE FROM config WHERE key = 'ui_v3_enabled';` | **다음 요청부터** 꺼짐 (38ms · 첫 요청에 바로) |

```js
// ① — 사이트 아무 화면에서, 관리자 계정으로. 200 이 나오면 꺼진 것이다
fetch("/api/settings/platform", { method: "PUT", headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ uiV3: false }) }).then((r) => r.status)
```

켜는 것도 같다: 로컬에서 켠 뒤 **첫 요청**이 이미 새 화면으로 갔다(115ms).
①은 활동 기록에 「플랫폼 설정 변경 — v3 화면 켜짐 → 꺼짐」 한 줄을 남긴다. ②는 기록이 안 남는다.

**끄면 옛 화면이 그대로 돌아온다.** 스위치는 **길만** 바꾼다 — 데이터는 한 벌이라 새 화면에서
만들거나 바꾼 업무는 옛 화면에서도 그대로 보인다. 되돌릴 데이터가 없다.

> 결정할 것 하나 — 켠 상태에서 **화면으로 끄는 길**을 둘지. 두려면 `/settings` 를 막음 목록에서
> 빼거나(옛 설정 화면이 켠 상태에서도 열린다) 새 화면 어딘가에 끄는 자리를 둬야 한다. 둘 다
> 새 규칙이라 이번에 안 했다.

## 켜면 옛 주소는 어디로 가나 — 로컬에서 **실제로 가 본** 곳

| 옛 주소 | 켠 뒤 (관리자) | 팀원이면 |
|---|---|---|
| `/` | `/v3` 대시보드 | 같다 |
| `/tasks` | `/v3/tasks` | 같다 |
| `/tasks?panel=task:33` | `/v3/tasks/33` — **그 업무 상세** | 같다 |
| `/goals` | `/v3/goals` | 같다 |
| `/members` | `/v3/members` | **밀려남** 「관리자만 볼 수 있습니다」(`?denied=members`) |
| `/profile` | `/v3/me` | 같다 |
| 자물쇠 14곳(아래) | 막음 화면 `/v3/not-yet?k=…` (404 아님) | 같다 — 단 `/status` · `/open-due` 는 **밀려남**이 먼저다(원래 팀원이 못 보는 화면) |
| `/notifications` | `/activity` → 막음 화면(활동) — 두 번 옮겨 간다 | 같다 |
| `/timeline` | `/` → `/v3` — 두 번 옮겨 간다 | 같다 |
| `/admin/agent-usage` | ⚠ **옛 화면이 그대로 뜬다**(200) | 밀려남 |
| `/areas/<없는 번호>` | 404 — 스위치와 무관(원래 없는 영역) | 같다 |

⚠ `/admin/agent-usage`(에이전트 사용량 · 관리자만)는 짝표에도 막음 목록에도 없어서 **켠 뒤에도 옛
화면이 뜨는 유일한 자리**다. 에이전트 철거(071 §D-27)에 묶여 있어 이번에 손대지 않았다.

### 자물쇠(막음 화면) — **14곳**

`lib/v3/not-yet.ts` 한 파일이 목록이다. 줄을 지우면 그 화면이 열린다.

캘린더 · 프로젝트(아래 전부) · 시그널 · 승인 인박스 · 활동 · 허들룸 · 보고 · 인수인계 ·
저장한 보기 · 메모 · 시스템 상태 · 영역(아래 전부) · 가오픈 기한 · 설정

레일에 자물쇠로 서는 것은 넷(캘린더 · 프로젝트 · 영역 · 설정)이고, 나머지 열은 **주소로 들어오면**
막음 화면으로 간다. 막음 화면은 셋을 적는다 — 무엇인지 · 언제 열리는지 · 돌아갈 길.

### 켜면 열리는 새 화면 — 아홉

대시보드 · 업무 목록 · 업무 상세 · 새 업무 · 목표 · 집계 · 팀 · 구성원(관리자만) · 내 정보.
켜기 전에는 `/v3` 가 전부 「새 화면은 아직 꺼져 있습니다」로 간다(`/?denied=v3-off`, 로컬 확인).

## 켜기 전 점검 — 프로덕션에서 눈으로 볼 것 (아홉)

**켜기 전**
1. `/v3` 를 열면 「새 화면은 아직 꺼져 있습니다」가 뜨는가 — 지금 꺼져 있다는 확인
2. 관리자 계정으로 `/settings` 에 v3 스위치가 보이는가 — 켜는 자리
3. 위 ① 끄는 명령을 **복사해 둔다** — 켠 뒤에는 화면으로 못 끈다

**켠 직후**
4. `/` 가 새 대시보드로 가는가 — 타일 넷 · 내 업무 · 분기 목표 · 영역별 남은 업무
5. 옛 상세 주소 `/tasks?panel=task:<번호>` 가 **그 업무의** 새 상세로 가는가
6. 레일의 자물쇠 하나(캘린더)를 누르면 막음 화면(404 아님)인가
7. 팀원 계정으로 `/members` 를 치면 밀려남(「관리자만」)인가
8. 대시보드 줄 하나를 체크 → 「되돌리기」 — 상태가 돌아오는가(073 §A: 진행률 편집자면 진행률도)

**끄기**
9. ① 명령이 200 을 내고, 곧바로 `/tasks` 가 **옛 업무 화면**으로 뜨는가

---

### 이 문서를 만든 측정

- 켜기·끄기 걸린 시간 — 켜기(API) 115ms · 끄기(API) 83ms · 끄기(줄 삭제) 38ms, 셋 다 **첫 요청에 반영**
- 옛 주소 24곳 × 관리자·팀원 — 위 표
- 측정 뒤 스위치는 **행 없음(꺼짐)** 으로 되돌렸고, ①이 남긴 활동 기록 3줄은 지웠다
