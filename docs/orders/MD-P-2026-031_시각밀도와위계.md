# §A 폰트 스케일과 행 높이

### A1. 스케일을 올린다
6단계 구조는 유지하고 값만 올린다. **단계를 늘리지 말 것.**

| 토큰 | 현재 | 변경 | 쓰임 |
|---|---|---|---|
| `--f1` | 25px | **26px** | 화면 제목 |
| `--f2` | 19px | **20px** | 카드/섹션 제목 |
| `--f3` | 14px | **15px** | 강조 본문 · 큰 수치 |
| `--f4` | 12.5px | **13.5px** | **본문 기본** · 목록 제목 |
| `--f5` | 11.5px | **12px** | 보조 · 수치 |
| `--f6` | 10.5px | **11px** | 라벨 · 메타 |

- `--f6` 아래는 만들지 않는다. **11px 미만 글자는 화면에 존재하지 않는다.**
- 하드코딩 `font-size` 를 전수 조사해 토큰으로 바꾼다. 개수 before/after 제출.
- **배율 100% 기준으로 검증한다.** 125% 에서 잘 보이는 것은 근거가 아니다.

### A2. 행 높이
- 목록 행 38px → **44px** / 그룹·섹션 헤더 34px → **38px**
- 이유는 밀도 완화가 아니라 **담당자 이름과 상태 알약이 들어갈 자리**다(§D).
- 44px 은 화면당 표시 건수를 줄인다. 그 대가는 §C1 이 회수한다.

### A3. 세로 정렬 — 549건
- 상자·셀·버튼 안 텍스트는 **예외 없이 세로 중앙**.
- 고치는 방법을 하나로 통일한다. `display:flex; align-items:center` 이거나,
  단일 줄은 `height` 와 같은 `line-height`. **한 컴포넌트에 두 방법을 섞지 말 것.**
- **여러 줄 텍스트 셀은 상단 정렬이 맞다.** 그 경우는 목록으로 따로 제출.
  무조건 중앙으로 밀지 말 것.

# §D 목록 행 규격

### D1. 영역 표시 — 상자를 없앤다

### D2. 상태 알약 — 테두리 없이 틴트만

  대체안(텍스트 · 색 점 · 삭제) 중 무엇으로 갔는지 표로 낼 것.

### D3. 좌측 색 띠 금지
- 카드·섹션 제목 왼쪽 3px 색 바를 **전부 제거**한다.
- 제목 무게는 타이포로 만든다. `--f3` 이상 / `font-weight:800` / `letter-spacing:-.028em`
- **헤더 배경칠 금지. 헤더 아래 구분선 금지.**
- 색 띠와 배경칠은 정보를 나누는 가장 손쉬운 수단이라, 반복하면 관리자 페이지가 된다.

### D4. 깊이는 선이 아니라 그림자
- 카드 테두리 → 그림자
  `--e-card: 0 1px 2px rgba(16,24,40,.04), 0 12px 28px -16px rgba(16,24,40,.18)`
  `--e-lift: 0 1px 2px rgba(16,24,40,.05), 0 16px 32px -14px rgba(16,24,40,.22)` (hover)
- 카드 radius 9px → **14px**. 행·입력·버튼 radius 는 4/7/9 유지.
- `--bg` `#F7F8F9` → **`#F4F6F8`**. 카드 흰색과의 대비 확보.

### D5. 담당자는 이름으로
- **아바타 이니셜(권 · 조 · 박) 금지. 이름 그대로.** `--f6` / 600 / `--muted`
- 둘이면 `권정혁 · 조서연`, 셋 이상이면 `권정혁 외 2`.
- 이니셜은 동성이 둘이면 즉시 무너진다. 우리 팀 규모에서 아바타는 장식이다.

  빈 값일 때 무엇을 그리는지(`담당 없음`)도 규격에 넣는다.

### D6. 간트 막대

  **문자 기호(▲ ● ▣ ▤ ↩ ◀)를 아이콘 자리에 쓰지 않는다.** 전수 교체 후 개수 제출.

# §E 버튼 · 색 정리

### E1. 버튼 규격을 다시 쓴다 — **기존 규격이 틀렸다**
감사 결과: 중립 채움은 코드에 **0개**인데 규격이 그것을 요구했고, 흰 채움은 **69개**로
가장 많은데 규격에 없었고, 높이 4px 배수는 **416개 중 317개가 위반**이다.
317 대 99 면 코드가 아니라 규칙이 틀린 것이다. 다수를 위반으로 몰지 말고 규격을 고친다.

**4종만 둔다.**

| 종류 | 쓰임 | 제한 |
|---|---|---|
| 코랄 채움 | 그 화면의 주액션 | **화면당 1개** |
| 흰 채움 + 1px 선 | 보조 액션 | 없음 |
| 투명 + 텍스트 | 3차 · 링크형 | 없음 |

## 2. C2-정렬의 URL — 승인, 그리고 이름을 지금 정한다
서버 정렬이면 정렬 변경 = 재요청이고, 주소가 안 남으면 새로고침에 초기화된다.
**§C1 의 적용 범위 확대이지 새 규칙이 아니다.**
다만 이름을 지금 정하지 않으면 4개 화면이 각자 짓는다. 아래로 고정한다.

### 2-1. 파라미터

    ?sort=manual|due|priority|created     정렬 기준
    &group=project|priority|due|none      묶는 기준 (§C2 셀렉트 3택 + 없음)
    &area=<id>                            영역 필터
    &assignee=<id>                        담당자 필터
    &q=<검색어>                            검색
    &status=<...>&resolution=<...>        기존 필터 규격 유지

- **4개 화면(홈 · 업무 목록 · 프로젝트 상세 · 영역 상세)이 같은 이름을 쓴다.**
  화면별 접두어를 붙이지 말 것. 같은 컴포넌트가 같은 주소 규약을 쓰는 것이 §C4 의 절반이다.
- 프로젝트 상세·영역 상세는 `area` / `project` 가 **경로에 고정**되어 있으므로
  쿼리로 중복해 쓰지 않는다.

### 2-2. 기본값은 주소에 쓰지 않는다
`sort=due` · `group=project` 가 기본이면 주소에 안 적는다.
전부 적으면 홈 주소가 매번 파라미터 여섯 개짜리가 되고, 그걸 복사해 공유하면
받는 사람이 무엇이 의도된 설정인지 못 가린다. **주소에 남은 것 = 사용자가 바꾼 것.**

### 2-3. 뒤로가기 — `replaceState`
- 정렬·묶기·필터 변경은 **history 를 쌓지 않는다.** `replaceState` 로 주소만 갱신한다.
- 정렬을 다섯 번 바꾼 뒤 뒤로가기를 누르면 이전 화면으로 나가야지,
  정렬 이력을 다섯 번 거슬러 올라가면 안 된다.
- **예외: 화면 이동(§C1 타일 클릭 → 목록)은 `pushState`.** 그건 진짜 이동이다.
- 검증: 타일 클릭 → 정렬 3회 변경 → 뒤로가기 1회 = 홈. 실측할 것.

### 2-4. 잘못된 값
`?sort=zzz` 같은 값이 오면 400 을 내지 말고 **기본값으로 조용히 떨어뜨린다.**
주소는 사람이 손으로 고치기도 하고 오래된 링크가 돌아다니기도 한다.
단 그 경우 주소를 기본값으로 정정해 `replaceState` 한다. 틀린 주소를 그대로 두지 않는다.
