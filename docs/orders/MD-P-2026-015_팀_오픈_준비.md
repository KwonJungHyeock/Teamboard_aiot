# 작업지시서 — 팀 오픈 준비 (MD-P-2026-015)
발행 2026-08-04 · 선행: MD-P-2026-014 완료

## 목적
팀원 전체에게 정식으로 여는 단계. **신규 사용자가 설명 없이 쓸 수 있는가**와
**운영 중 사고가 나지 않는가** 두 가지를 확보한다. 새 기능 추가는 하지 않는다.

## A. 첫 사용 경험
- **첫 로그인 시 1회 안내**(모달 3장, 건너뛰기 가능, 다시 보지 않기 저장):
  1) "프로젝트 안에서 논의·업무·기록·결정이 끝납니다"
  2) "⌘K 로 어디든 이동, ⌘/ 로 단축키 전체 보기"
  3) "목표에 프로젝트를 연결하면 달성률이 자동 계산됩니다"
- ⌘/ 단축키 모달 하단에 `처음이신가요? 안내 다시 보기` 링크.
- **Slack 사용자 대상 문구**로 작성할 것(스레드·활동·저장됨 등 익숙한 용어 사용).

## B. 데이터 정리
- 개발 중 생성된 **테스트 데이터 전수 확인** 후 목록 제출. (삭제는 승인 후 실행 — 임의 삭제 금지)
- 실제 업무 데이터 정합 확인: 담당자 미지정·기간 역전(종료<시작)·영역 미지정 항목 목록화.
- 목표에 연결되지 않은 프로젝트 목록 제출(오픈 전 연결 유도용).

## C. 권한 점검 (전수)
- 개인 목표: 본인·팀장 외 접근 시 403 확인
- 월간 보고 `승인 보고서`: 팀장 전용 확인
- 관리 화면: 관리자 외 접근 차단 확인
- **URL 직접 접근**으로 우회되지 않는지 각 항목 실제 테스트(클라이언트 숨김만으로 처리된 곳 색출)

## D. 안정성
- 전역 에러 바운더리 + **404 / 500 페이지**(브랜드 적용, 홈 복귀 CTA)
- 주요 목록 화면의 N+1 쿼리 점검. 홈·활동·프로젝트 상세 응답시간 계측값 제출
- **로그인 → 홈 진입 e2e 스모크 테스트**(MD-P-008 D-4 요구분) 존재 확인. 없으면 추가하고 CI에 연결
- Neon 백업·복구 설정 상태 확인 후 보고

## E. 운영 문서 (`docs/` 에 작성)
- `docs/RUNBOOK.md` — 배포 절차, 롤백 방법, Cron(스냅샷) 확인법, 장애 시 1차 대응
- `docs/ONBOARDING.md` — 팀원용 사용 안내(화면별 1문단, 단축키 표 포함)

## 제약
- **새 기능 추가 금지.** 안내·점검·문서화만.
- 데이터 삭제는 목록 제출 후 승인받고 실행.
- 시각 토큰 변경 금지.
