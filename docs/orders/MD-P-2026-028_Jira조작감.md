## §A 하위 업무

### A1. 업무 상세 — 속성 블록 아래에 붙인다

새 화면을 만들지 않습니다. 문서형 업무 상세의 속성 블록 아래, 자유 본문 위에 둡니다.

- 제목 줄: `하위 업무 3 · 완료 1`
- 38px 행 목록. 열은 체크박스 · 제목 · 담당 · 기한 · 진척.
- 맨 아래에 인라인 추가 한 줄. `InlineTaskInput` 을 그대로 재사용할 것.
  **세 번째 자리입니다. 새로 만들면 Enter 동작이 갈립니다.**
- 하위가 0건이면 섹션 빈 상태(한 줄) + 인라인 추가만 보입니다.

### A2. 상속과 금지

- 하위 업무는 프로젝트·영역을 상위에서 상속합니다. 따로 고르게 하지 마세요.
- 하위 업무는 목표에 직접 연결할 수 없습니다. 상위를 통해서만 집계됩니다.
  030 으로 목표에 닿는 길이 `goal_task` 하나가 됐으므로,
  하위 업무의 `goal_task` INSERT 를 서버에서 막고 **사유 문구를 실측해 첨부할 것.**
  (지금은 막혀 있지 않고, 붙여도 진척에 안 잡히는 조용한 실패가 열려 있습니다)
- 공개 범위도 상위를 따릅니다. 상위가 팀이면 하위도 팀입니다.
- 깊이 2단은 DB 가드가 이미 있습니다. UI 에서는 하위 업무의 상세에
  "하위 업무" 섹션 자체를 그리지 마세요. **눌러도 안 되는 것을 보이지 않게 합니다.**

### A3. 목록 화면에서의 표시

- 기본은 접힘. 하위가 있는 행의 왼쪽에만 펼침 캐럿을 그립니다.
- 펼치면 22px 들여쓰기로 하위 행이 붙습니다. **목표 트리와 같은 들여쓰기 값**을 쓸 것.
- 높이를 애니메이트하지 않습니다(§H2 금지 속성).
  펼침 자체는 즉시, **나타나는 행에만** `opacity` + `translateY(-4px)` 를 `--dur-2` 로.
- 하위 행은 필터·정렬의 대상이 아닙니다. 상위가 걸리면 따라 나옵니다.
  하위만 걸리면 **상위를 살려서** 보여줍니다 — 목표 트리의 재귀 CTE 와 같은 처리입니다.

### A4. 승격·강등

- 업무 상세 속성 블록의 "상위 업무" 를 비우면 최상위가 됩니다.
- 최상위 업무에 상위를 지정하면 하위가 됩니다.
  단 그 업무에 하위가 있으면 거부합니다(깊이 2단).
- 승격·강등 시 진척 집계가 **즉시** 재계산되어야 합니다.
  떠난 쪽과 새로 붙은 쪽 양쪽입니다.
