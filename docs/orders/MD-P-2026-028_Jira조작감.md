## §A 하위 업무

### A1. 업무 상세 — 속성 블록 아래에 붙인다

새 화면을 만들지 않습니다. 문서형 업무 상세의 속성 블록 아래, 자유 본문 위에 둡니다.

- 제목 줄: `하위 업무 3 · 완료 1`
- 38px 행 목록. 열은 체크박스 · 제목 · 담당 · 기한 · 진척.
- 맨 아래에 인라인 추가 한 줄. `InlineTaskInput` 을 그대로 재사용할 것.
  **세 번째 자리입니다. 새로 만들면 Enter 동작이 갈립니다.**
- 하위가 0건이면 섹션 빈 상태(한 줄) + 인라인 추가만 보입니다.

### A2. 상속과 금지

- 하위 업무는 프로젝트·영역을 상위에서 상속합니다. 따로 고르게 하지 마세요.
- 하위 업무는 목표에 직접 연결할 수 없습니다. 상위를 통해서만 집계됩니다.
  030 으로 목표에 닿는 길이 `goal_task` 하나가 됐으므로,
  하위 업무의 `goal_task` INSERT 를 서버에서 막고 **사유 문구를 실측해 첨부할 것.**
  (지금은 막혀 있지 않고, 붙여도 진척에 안 잡히는 조용한 실패가 열려 있습니다)
- 공개 범위도 상위를 따릅니다. 상위가 팀이면 하위도 팀입니다.
- 깊이 2단은 DB 가드가 이미 있습니다. UI 에서는 하위 업무의 상세에
  "하위 업무" 섹션 자체를 그리지 마세요. **눌러도 안 되는 것을 보이지 않게 합니다.**

### A3. 목록 화면에서의 표시

- 기본은 접힘. 하위가 있는 행의 왼쪽에만 펼침 캐럿을 그립니다.
- 펼치면 22px 들여쓰기로 하위 행이 붙습니다. **목표 트리와 같은 들여쓰기 값**을 쓸 것.
- 높이를 애니메이트하지 않습니다(§H2 금지 속성).
  펼침 자체는 즉시, **나타나는 행에만** `opacity` + `translateY(-4px)` 를 `--dur-2` 로.
- 하위 행은 필터·정렬의 대상이 아닙니다. 상위가 걸리면 따라 나옵니다.
  하위만 걸리면 **상위를 살려서** 보여줍니다 — 목표 트리의 재귀 CTE 와 같은 처리입니다.

### A4. 승격·강등

- 업무 상세 속성 블록의 "상위 업무" 를 비우면 최상위가 됩니다.
- 최상위 업무에 상위를 지정하면 하위가 됩니다.
  단 그 업무에 하위가 있으면 거부합니다(깊이 2단).
- 승격·강등 시 진척 집계가 **즉시** 재계산되어야 합니다.
  떠난 쪽과 새로 붙은 쪽 양쪽입니다.

## §B 차단 관계

### B1. 지정 — 읽기 전용을 편집 가능으로

속성 블록의 "차단" 행은 지금 읽기 전용 링크입니다. 검색형 콤보박스로 바꿉니다.
**`ProjectCombo` 패턴을 재사용하고 새 컴포넌트를 만들지 마세요.**

- 타이핑으로 좁힙니다. 최근 본 업무를 위에 둡니다.
- 자기 자신·순환은 서버가 이미 409 로 막습니다. **그 사유 문장을 그대로 보여줄 것.**
- "차단 없음" 을 고를 수 있어야 합니다. 지정만 되고 해제가 안 되면 안 쓰입니다.
- 기존 `blocked_reason`(사유 텍스트)은 지우지 마세요. 업무로 지목할 수 없는 차단도
  있습니다. 두 값이 함께 보이되, **지목이 있으면 그것이 먼저 읽히게** 배치할 것.

### B2. 역방향 — 이것이 Jira 에서 가져올 진짜 값입니다

"무엇이 나를 막는가" 만 보이면 절반입니다. **"내가 무엇을 막고 있는가"** 가 보여야 합니다.
남이 나 때문에 못 나가고 있다는 걸 본인만 모르는 상황이 가장 흔합니다.

- 속성 블록에 "이 업무가 막는 업무" 줄을 추가합니다. 0건이면 줄을 그리지 않습니다.
- 이 줄은 **읽기 전용**입니다. 역방향은 상대 업무에서 지정한 것이므로 여기서 고치지 않습니다.
- 값이 있으면 개수와 링크를 보입니다. `2건 — #41, #47`

### B3. 목록에서의 표시

- 차단된 행에 "차단됨" 칩. **코랄을 쓰지 마세요.** 코랄은 화면당 주액션 1개입니다.
  기존 상태 칩 규격을 그대로 쓰고 색은 `--amber` 계열 틴트.
- 칩을 누르면 원인 업무로 이동합니다.
- 지목 없이 사유 텍스트만 있는 차단도 같은 칩을 씁니다.
  칩을 눌렀을 때 갈 곳이 없으면 사유를 툴팁으로 보입니다.

### B4. 원인이 풀렸을 때

- 차단 원인 업무가 완료되면 **자동으로 해제하지 않습니다.**
  원인이 끝나도 다른 이유로 여전히 막혀 있을 수 있습니다.
- 대신 차단된 업무에 안내를 띄웁니다.
  `차단 원인 #39 가 완료됐습니다 — 차단 해제`
  해제는 그 자리에서 한 번에 되어야 합니다.
- 이 안내는 **활동에도 남깁니다.** 사람이 화면을 안 보고 있을 수 있습니다.

## §C 백로그 드래그 정렬

### C1. 언제 드래그가 되는가

`sort_order` 는 023 에서 이미 들어가 있고 UI 만 없습니다.
조사에서 47건에 값이 흩어져 있는 것을 확인했으니 쓸 값은 있습니다.

- 정렬 기준이 **"수동 순서"** 일 때만 드래그됩니다.
- 기한순·우선순위순·생성순일 때는 드래그 핸들을 그리지 않고,
  정렬 셀렉트 옆에 한 줄 안내를 둡니다.
  `순서를 바꾸려면 정렬을 '수동 순서'로 바꾸세요`
  **잡히지 않는 핸들을 보여주면 고장으로 읽힙니다.**

### C2. 조작

- 핸들은 행 왼쪽, hover 와 키보드 포커스에서만 노출. 6점 그립.
- 드롭 중에는 놓일 자리에 1px 코랄 선. **행을 미리 벌리지 마세요**(높이 애니메이트 금지).
- 이동 후 재정렬은 §H3 의 FLIP(`useFlip`, `--dur-3`)을 그대로 씁니다. 새 모션 금지.
- 키보드: 핸들에 포커스한 상태에서 `⌥↑` / `⌥↓` 로 한 칸씩 이동.
  드래그만 되는 기능은 접근성 이전에 노트북 트랙패드에서 불편합니다.

### C3. 범위

- **같은 부모 안에서만** 순서가 바뀝니다. 드래그로 부모를 바꾸지 않습니다.
  부모 변경은 §A4 의 속성 편집으로 합니다. 두 가지를 한 제스처에 얹으면 오조작이 납니다.
- 하위 업무도 같은 상위 안에서 서로 순서를 바꿀 수 있습니다.
  상위 업무 사이로 끌어낼 수는 없습니다.
- 필터가 걸린 목록에서도 드래그는 가능하되, 저장되는 것은 **전역 `sort_order`** 입니다.
  필터 때문에 안 보이는 행 사이에 끼는 경우를 서버에서 정리할 것.
