# 작업지시서 — 성과 스냅샷 적립 (MD-P-2026-011)
발행 2026-08-04 · 선행: MD-P-2026-010 완료

## 목적
MD-P-2026-010 구현 중 확인된 문제 해소. 목표 진척은 **현재값만 존재**하고 시점 기록이 없어
과거 월 리포트가 전부 "기록 없음"으로 남는다. 소급 추정은 금지했으므로, **지금부터 적립**을 시작한다.
**시급함**: 미루는 만큼 빈 구간이 늘어난다.

## 범위
- 스냅샷 테이블 + 정기 작업 + 월별 리포트 연동.
- 화면 변경 최소. 신규 페이지 생성 금지.

## A. 스키마
`goal_snapshot` 신규:
- `id`, `goal_id`(FK), `snapshot_date`(DATE, KST 기준)
- `progress`(int), `status`, `linked_project_count`(int), `source`('auto'|'manual')
- `captured_at`(timestamptz)
- **UNIQUE (goal_id, snapshot_date)** — 재실행 시 upsert

업무는 스냅샷 불필요(`completed_at` 등 이벤트로 과거 조회 가능). **목표 진척·상태만 적립.**

## B. 적립 주기 — 일 1회
- **매일 1회** 스냅샷(월말 1회 아님).
- 근거: 월말 날짜가 달마다 달라 월말 트리거는 오작동 위험이 크고, 일별이면 월중 추이 조회도 가능하다.
  데이터량은 목표 수 × 365로 무시할 수준.
- 실행 시각: **KST 00:10** (Vercel Cron은 UTC이므로 `10 15 * * *`). 전일 마감 기준으로 기록.
- `vercel.json`의 `crons`에 등록. 엔드포인트는 인증된 내부 경로(외부 호출 차단).

## C. 배포 직후 1회 즉시 실행
- 배포 시점에 **오늘자 스냅샷 1건 생성**(source='auto'). 8월 데이터를 살리기 위함.
- **과거 월 소급 생성 금지.** 없는 구간은 계속 "기록 없음"으로 둔다(추정 금지 원칙).

## D. 수동 스냅샷
- 목표 페이지 우상단 `⋯ → 지금 스냅샷 저장` (팀장 전용). source='manual'.
- 같은 날 재실행 시 덮어쓰기(upsert). 토스트로 결과 표시.

## E. 월별 리포트 연동 (MD-P-2026-010 보완)
- **해당 월 값 = 그 달의 마지막 스냅샷.**
- **전월 대비 증감 = 이번 달 마지막 스냅샷 − 전월 마지막 스냅샷.** 둘 중 하나라도 없으면 증감 미표시.
- 스냅샷이 하나도 없는 월은 기존대로 "기록 없음" 유지.
- 목표 상세에 **월별 추이 미니 차트**(최근 6개월, 스냅샷 있는 달만 점으로 표시). 없는 달은 선을 잇지 말 것.

## F. 실패 처리
- Cron 실패 시 활동 인박스 **시스템 탭**에 알림 1건(MD-P-2026-007 §B 분류 준수).
- 연속 2회 실패 시에만 알림(1회 실패는 재시도).
- 실행 이력 로그(성공/실패·건수·소요시간) 조회 가능하게.

## 제약
- add-only 마이그레이션. 기존 데이터 변경 금지.
- 스냅샷 값은 서버 집계(`lib/goals.ts`) 결과를 그대로 저장. 별도 계산식 금지.
- 없는 데이터를 0으로 채우지 말 것.
