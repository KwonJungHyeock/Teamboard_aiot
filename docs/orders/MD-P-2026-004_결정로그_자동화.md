# 작업지시서 — 결정 로그 자동화 (MD-P-2026-004)

## 목적
논의를 "해결"하면 **결정이 자동으로 프로젝트 결정 로그에 기록**되게 한다.
근거: Slack 벤치마킹 결과, 개발팀 최대 실패 모드가 "결정이 스크롤에 묻혀 재논의됨"이고
Slack 팀들은 이를 수동 캔버스/외부 ADR로 때우고 있다. 우리는 이걸 자동화해 구조적 우위를 만든다.

## 범위
- 논의·결정 페이지, 프로젝트 상세, 홈 "결정 대기" 모듈, DB 스키마.
- 다른 페이지 레이아웃 변경 금지.

## A. 데이터 모델
`decision` 테이블 신규:
- id, project_id, discussion_id(FK), title(결정 내용 한 줄), rationale(근거·본문),
  decided_by(user), decided_at(timestamp), status('확정'|'번복'), superseded_by(nullable FK→decision.id),
  linked_task_ids(배열, 선택)
- 인덱스: project_id, decided_at

## B. 논의 → 결정 전환 플로우
1. 논의 상세 상단 [✓ 해결로 표시] 클릭 → **결정 확정 팝오버**(화면 이동 금지):
   - `결정 내용` 1줄 입력 (필수, 기본값 = 논의 제목 프리필)
   - `근거` 본문 (선택, 스레드 마지막 3개 답글을 요약 프리필 — 사용자가 수정 가능)
   - `연결 업무` 멀티선택 (선택)
   - [확정] 버튼
2. 확정 시:
   - `decision` 레코드 생성, 논의 status → '해결'
   - 논의 스레드 하단에 **결정 카드 고정**(초록 LED + 결정 내용 + 결정자 + mono 타임스탬프)
   - 참여자 전원에게 알림("○○ 논의가 결정으로 확정됨")
3. **번복**: 결정 카드에 [번복] → 새 결정 생성 + 기존 결정 status='번복', superseded_by 연결.
   결정 로그에서 번복된 항목은 취소선 + "→ 새 결정 #ID" 링크로 표시(삭제 금지).

## C. 결정 로그 화면
- 위치: 프로젝트 상세 내 탭 `결정 로그` + 전역 `논의·결정` 페이지에 `결정` 탭 추가.
- 목록 행(통일 카드): 결정 내용 / 프로젝트·영역 칩 / 결정자 아바타 / `decided_at`(mono) / 원본 논의 링크 / 연결 업무 수
- 정렬 기본 = 최신순. 필터: 프로젝트, 결정자, 기간, 상태(확정/번복).
- 검색: 결정 내용 + 근거 본문 대상 텍스트 검색.
- 빈 상태: "아직 확정된 결정이 없어요. 논의를 해결하면 여기에 자동으로 쌓입니다."

## D. 홈 연동
- 기존 "결정 대기" 모듈 하단에 **"이번 주 확정된 결정 N건"** 요약 줄 추가 → 클릭 시 결정 로그로 이동.
- 카운터를 늘리지 말 것. 한 줄 텍스트 링크로만.

## E. 양방향 링크 (Slack 패턴 이식)
- 결정 → 원본 논의 링크 (필수)
- 원본 논의 → 결정 카드 (고정 표시)
- 연결 업무 상세에 "관련 결정" 섹션 (결정 내용 + 링크)

## 제약
- 결정은 **삭제 불가**, 번복만 가능(감사 추적 유지).
- `rationale` 자동 프리필은 반드시 **사용자가 수정 가능**해야 하며, 저장 전 초안임을 명시.
- 디자인: 기존 Mission Deck OS 토큰 사용. 결정=green LED, 번복=slate 취소선.
- 접근성 4.5:1, reduced-motion 대응.
