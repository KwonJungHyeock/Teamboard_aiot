# 작업지시서 — 캔버스 이미지 활성화 + 스크림 통일 (MD-P-2026-014)
발행 2026-08-04 · **선행 필수: Vercel Blob 스토어 연결 완료**

## 목적
MD-P-2026-005에서 UI만 만들고 비활성으로 둔 **캔버스 이미지 블록을 실제 동작**시킨다.
팀이 Figma로 만든 설계·이미지 기록을 프로젝트 캔버스에 붙일 수 있게 하는 것이 목적이며,
이로써 "과정 기록의 본체" 요구가 완성된다. 동시에 MD-P-013 보류 1건(스크림 규격)을 해소한다.

## 선행 확인
- `BLOB_READ_WRITE_TOKEN` 존재 확인. **없으면 작업 중단하고 보고할 것.**
- 미연결 시 기존 비활성 상태(툴팁 안내)를 그대로 유지해야 하며, 깨진 업로드 UI 노출 금지.

## A. 이미지 업로드
- 진입: 캔버스 블록 메뉴 `이미지` / **드래그앤드롭** / **붙여넣기(⌘V)** 모두 지원.
- 제한: 형식 `png·jpg·webp·gif`, **개당 10MB**. 초과·미지원 형식은 업로드 전 차단 + 사유 토스트.
- 업로드 중 표시: 자리 확보한 스켈레톤 + 진행률. 실패 시 [다시 시도] 버튼(블록 사라지지 않게).
- 저장: Blob에 업로드 후 URL을 캔버스 block(JSONB)에 기록. **원본 파일명·크기 함께 저장.**

## B. 이미지 표시
- 기본: 캔버스 폭에 맞춤. 클릭 시 라이트박스(Esc 닫기, reduced-motion 시 애니 없음).
- 캡션 입력(선택). 이미지 hover 시 액션바(캡션·교체·삭제) — 기존 hover 액션바 규격 준수.
- `alt` 텍스트: 캡션이 있으면 캡션, 없으면 파일명. 빈 alt 금지(접근성).

## C. 삭제·정리
- 블록 삭제 시 Blob 객체도 삭제(고아 파일 방지). 삭제 실패는 로그만 남기고 UI는 진행.
- 캔버스 자체 삭제·프로젝트 보관 시에는 **Blob 유지**(보관은 삭제가 아님).

## D. 동시 편집 정합 (MD-P-013 수정분 준수)
- 이미지 블록 추가·삭제도 `baseUpdatedAt` 낙관적 동시성 경로를 그대로 탈 것.
- 업로드 중 409가 오면 업로드된 파일은 살리고 최신본에 재부착 시도, 실패 시 사유 안내.

## E. 함께 활성화할 것
Blob 대기로 막혀 있던 나머지도 같이 켠다:
- 리뷰(허들룸) 모드의 **이전/이후 이미지 첨부**
- 논의·코멘트의 이미지 첨부
- 위 경로 모두 A~D 규칙 공통 적용(중복 구현 금지, 업로드 모듈 1개 공유)

## F. 스크림 규격 통일 (MD-P-013 보류 1건)
- `.modal-backdrop` 이 순검정 `.6` 인데 다른 스크림은 차콜 틴트 `.34~.55`.
- **모든 스크림을 차콜 틴트로 통일**하고 토큰 1개로 정의. 값은 기존 다수값(차콜 `.45` 전후)에 맞출 것.
- 라이트박스 스크림도 같은 토큰 사용.

## 제약
- 업로드는 서버 라우트 경유. 토큰 클라이언트 노출 금지.
- 이미지 로딩이 캔버스 렌더를 막지 않을 것(lazy).
- 시각 토큰 신규 생성은 스크림 1개만 허용. 그 외 추가 금지.
- 대비 4.5:1, reduced-motion 준수.
