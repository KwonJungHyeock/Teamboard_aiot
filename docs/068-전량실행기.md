## 정한 값 셋 — **071 재는 판(72개 · 서버 하나 · 51분 1초)에서 읽었다**

| 값 | 정한 것 | 근거 |
|---|---|---|
| N (몇 개마다 새로 띄우나) | **16** | `/login` 이 1~16번째 중앙 66~69ms(최대 113ms) → **17번째 묶음부터 중앙 145ms 로 두 배.** 같은 자리에서 rss 가 2.3GB 를 넘는다. 느려지기 시작하는 자리 바로 앞 |
| 느림 기준치 | **250ms** | 빠른 구간 최대 113ms 의 두 배 남짓. 16개마다 새로 띄우면 여기 안 닿아야 한다. 닿으면 「못 쟀다(느려짐)」로 가르고 **바로** 새로 띄운다 |
| 시한 (검사기 하나) | **600초** | 가장 긴 둘이 `v3-switch-walk` 490초 · `area-project-walk` 467초(둘 다 느려진 서버 위). 가장 긴 것에 두 할쯤. 넘으면 「못 쟀다(시간 초과)」 — 빨강이 아니다 |

「넉넉히 10개마다」로 짐작하지 않았다(068 §B-4). 067 의 5초는 이번 재는 판에서는 안 나왔다 —
`/login` 최대 519ms(72번째). 느려지는 것은 계단 모양이었다: 17번째에서 한 번, 57번째에서 한 번.

# 전량 실행기 — 재는 판 **중간 기록** (MD-P-2026-068 §B · 069 §0 에서 멈춤)

069 §0: 「068 §B 는 지금 상태 그대로 멈춘다. 다음 회차에 이어서 한다.」
그래서 **N(몇 개마다 새로 띄우나)과 느림 기준치는 아직 안 정했다.** 아래는 재는 판
(`node scripts/suite.mjs --probe` — 서버 하나, 새로 안 띄움)이 **23/70** 에서 멈춘 기록이다.

- 5번째 `area-project-walk` 가 **469초** — 다른 것의 열 배쯤이다. 따로 볼 것
