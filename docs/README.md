# 문서 규칙 (MD-P-2026-021)

Mission Deck(팀보드) 산출물의 보관 규칙과 문서번호 체계를 정의한다.

---

## 1. 단일 원천 원칙

- **이 리포지토리가 프로젝트 산출물의 단일 원천이다.** 지시서·보고서·시안·계측 원본·캡처는 모두 여기에 둔다.
- **CC(Claude Code)는 리포지토리 안에만 쓴다.** 외부 폴더 경로를 참조하거나 문서에 기록하지 않는다.
- **지시서가 리포 밖 경로를 가리키면, CC는 그 사실을 먼저 보고하고 진행 여부를 묻는다.** 임의로 추측해 진행하지 않는다.

> 이 원칙은 MD-P-2026-019에서 시안 `03_디자인시안/05_개편_핵심3화면.html` 이 리포지토리 밖에 있어
> CC가 참조하지 못한 사고를 계기로 확정됐다.

---

## 2. 폴더 구조

```
docs/
├ README.md          이 문서. 폴더 규칙·문서번호 체계
├ SPEC.md            제품 명세
├ RUNBOOK.md         운영·배포·롤백·장애 대응
├ ONBOARDING.md      팀원용 사용 안내
├ CHANGE-GUIDE.md    변경 가이드
├ NOTION_SETUP.md    Notion 연동 설정
├ orders/            작업지시서            MD-{구분}-{연도}-{번호}_{제목}.md
├ reports/           완료·감사 보고서      MD-{구분}-{연도}-{번호}_{완료보고|감사보고}.md
├ design/            시안 HTML
├ audit/             계측 원본 JSON
├ shots/             캡처 (문서번호 폴더로 묶음)
└ archive/           구버전·폐기 문서
```

| 폴더 | 넣는 것 | 넣지 않는 것 |
| --- | --- | --- |
| `orders/` | 발행된 작업지시서 원문 (받은 그대로) | 진행 메모, 중간 결과 |
| `reports/` | 지시서 1건당 완료·감사 보고서 1건 | 계측 원본 JSON, 캡처 |
| `design/` | 시안 HTML, 목업 | 구현된 앱 코드 |
| `audit/` | 계측 스크립트가 뽑은 원본 JSON | 사람이 정리한 표 (보고서로) |
| `shots/` | 검증 캡처 PNG/PDF | 제품에 실제로 쓰이는 이미지 (`public/`) |
| `archive/` | 대체·폐기된 문서 | 현행 문서 |

---

## 3. 문서번호 체계

```
MD-{R|P|V|M}-{연도}-{일련번호}
```

| 구분 | 뜻 |
| --- | --- |
| `R` | 조사·검토 |
| `P` | 기획·지시 |
| `V` | 회고·QA |
| `M` | 월간성과 |

일련번호는 구분과 무관하게 연도 안에서 이어서 매긴다.

**파일명 예**

```
docs/orders/MD-P-2026-020_홈재구성_속성배선.md
docs/reports/MD-P-2026-020_완료보고.md
```

보고서 접미사는 성격에 따라 `_완료보고` 또는 `_감사보고` 를 쓴다.

---

## 4. 작업 흐름

1. 지시서가 `docs/orders/` 에 추가된다.
2. CC가 구현하고 `docs/reports/` 에 완료 보고서를 남긴다.
3. 캡처는 `docs/shots/{문서번호}/`, 계측 원본은 `docs/audit/` 에 둔다.
4. 시안은 `docs/design/` 에서만 참조한다.

### 캡처 보관 규칙

문서번호 폴더로 묶는다. 폴더 안 파일명은 원래 이름을 유지한다.

```
docs/shots/MD-P-2026-013/13-01-readline-before.png
docs/shots/MD-P-2026-013/13-01-readline-after.png
```

한 문서의 캡처가 몇 장뿐이어도 폴더를 만든다. 최상위에 낱개 파일을 두지 않는다.
