# MD-P-2026-032 §A — 상시 프로젝트 귀속 결과 (프로덕션 실측)

**이 문서가 유일한 근거다.** `0-1` 스냅샷을 건너뛰기로 했으므로 before 가 없다.
그러므로 **after 가 곧 기록**이고, 되돌릴 일이 생기면 아래 표가 유일한 출처다.

- 실행: `0029` → `0030` → `0031` (자동 마이그레이션, 프로덕션)
- 확인: PM 이 Neon 콘솔에서 직접 조회
- 관련: 경위 `러너-조사.md` · 절차 `A-프로덕션-절차.md` · 확인 SQL `A-사후확인.sql`

**남은 것 — 개인 업무 6건.** 프로젝트 없음이 **정상**이다.
`task_private_no_project`(0025) 가 개인 업무의 프로젝트 귀속을 금지한다.

### 왜 29 를 믿을 수 있는가

두 갈래가 맞물린다.

- 위 표의 합 = **29**
- 사후 확인 ③ 「프로젝트 없는 활성 **팀** 업무」 = **0**

한쪽은 옮겨진 것을 세고, 한쪽은 안 옮겨진 것이 없음을 센다.
**둘이 따로 세어 같은 결론에 닿았다.** 한 값만으로는 「옮겨졌다」와
「세다가 빠뜨렸다」를 구분할 수 없다.

### 영역이 안 바뀌었다는 근거

영역 분포 before/after 대조는 **못 했다**(before 가 없다). 대신 논리로 닫는다.

`0031` 은 `p.area_id = t.area_id` 인 상시 프로젝트로만 보내고,
`trg_task_area_match` 가 그 일치를 강제한다. 그러므로
**사후 확인 ④(영역 불일치) 가 0 이면 영역은 안 바뀐 것이다.**

## 눈에 띄는 것 — §B·§C 에서 볼 재료

**교육자료 상시가 10건으로 가장 크다.**

§C 에서 교육자료를 **메인 영역**으로 확정했다(커리큘럼 목표가 62% 로 돌고 있어서).
그런데 정작 그 영역 업무 10건이 **목표에 안 붙어 있다.**

> **지금 판단하지 않는다.**

§B 가 프로젝트 옮기기를 3초로 만든 뒤, PM 이 `A3-귀속대상.md` 표를 보며 하나씩
옮길 때 드러날 값이다. **§C3 「계획 외 투입」 지표가 정확히 이것을 센다** —
목표에 안 붙은 채로 도는 일이 얼마나 되는가.

지금 추정으로 붙이면 그 지표가 재려던 것을 미리 지워 버린다.
